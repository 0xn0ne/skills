## 1. 使用方式

第一步确定文体后，读对应一节：**必答问题**用于生成缺口清单；**常见主线**用于设计章节地图（用户指定结构时优先遵守）；**专属规则**是该文体在通用规则之上的补充或例外。文体不在列表中时，按"最接近的文体 + SKILL.md §0 三问"推断。

---

## 2. 分析 / 研究 / 评估报告

**侧重**：客观性、真实性、分析深度。价值在于提炼规律和判断，不是罗列事项。

**必答问题**：

1. 结论是什么？（一句话，放摘要）
2. 结论基于什么证据？证据的来源和可靠程度如何？
3. 为什么这些证据支持这个结论？（推理链）
4. 有哪些替代解释或反例？为什么不成立或影响有限？
5. 对读者意味着什么？（影响、风险、机会）
6. 建议下一步做什么？谁做？

**常见主线**：摘要（结论）→ 背景与问题界定 → 方法与数据来源 → 发现（按重要性排序，每个发现 = 判断 + 证据 + 解读）→ 综合判断 → 建议 → 附录（原始数据、方法细节）

**专属规则**：

- 事实、他人观点、作者推断三者在措辞上可区分："数据显示……""受访者认为……""我们据此判断……"
- 评估类必须先说清评估标准/维度，再给分数或等级；没有标准的评分是空泛（R4）
- 每个"发现"章节用结论型标题（H1）

---

## 3. 调研报告

**侧重**：用事实和数据说话；科学选题、合理取材、精深加工、对策有创见。

**必答问题**：

1. 调研什么问题？为什么现在调研？
2. 调研了谁 / 什么？样本怎么选的？用了什么方法？局限是什么？
3. 发现了什么？（数据、事实）
4. 这些发现说明了什么？（规律、原因、趋势）
5. 建议做什么？可操作到什么程度？

**常见主线**：调研背景与目的 → 调研对象与方法（含局限）→ 主要发现（分主题，数据先行）→ 分析与判断 → 对策建议 → 附录（问卷、原始数据、访谈提纲）

**专属规则**：

- **方法与局限必须写**：样本量、时间范围、覆盖范围、可能的偏差。不写局限的调研报告会被有经验的读者直接质疑
- 三分法严格执行：调研数据（事实）/ 受访者观点（观点）/ 作者分析（推断），不混写
- 对策必须回扣发现：每条对策能指向它要解决的哪个发现

## 4. 方案 / 提案 / 规划

**侧重**：前瞻性、创新性、指导性；读者读完能据此启动工作。

**必答问题**：

1. 解决什么问题？现状与目标的差距是什么？
2. 怎么做？（方法、步骤、工具、阶段）
3. 谁做、何时做？（角色、时间线、里程碑）
4. 做到什么标准算成功？（可验收的指标）
5. 需要什么条件？（预算、人员、权限、配合）
6. 有哪些风险？触发条件、影响、应对预案？
7. 为什么是这个方案而不是别的？（比较维度和取舍）

**常见主线**：问题与目标 → 整体思路（为什么这样设计）→ 分阶段/分模块展开 → 资源与组织 → 风险与预案 → 假设与前提 → 附录

**专属规则**：

- "整体思路"章不可省：它是后续所有章节的锚点（见 examples.md 正例 2）
- 多方案比较必须给维度和标准，再给推荐，再说取舍（内容之柱）
- 时间线用表格（H5），但表后必须解读关键路径和风险节点（H2）

## 5. SOW / 工作说明书

**侧重**：边界清晰、责任明确、可验收。它是后续争议的裁决依据。

**必答问题**：

1. 做什么？不做什么？（范围内 / 范围外都要写）
2. 每项工作怎么做？输入是什么、过程是什么、输出是什么？
3. 双方各承担什么？对方需要提供什么？缺位时怎么处理？
4. 交付什么？何时交付？怎么验收？验收标准是什么？
5. 假设与前提是什么？什么情况下范围/时间/费用需要重议？

**常见主线**：项目概述与目标 → 服务范围（范围内/外）→ 工作内容分项展开（每项：目标、方法、双方职责、产物）→ 时间与里程碑 → 交付物与验收 → 双方职责汇总 → 假设、前提与变更 → 附录

**专属规则**：

- 每项服务用"五个具体"逐项检查，尤其是方法具体和产物具体
- 术语一致视同红线：已定义术语（"重要系统""工作日""严重漏洞"）出现不一致会成为争议点
- 兜底句严格执行 R6，全部收纳到"假设、前提与变更"章
- 责任矩阵表适合表格，但表后必须解读关键依赖（对方不做 X 我方就无法做 Y）

---

## 6. 制度 / 规范 / 流程

**侧重**：权威性、约束力、可执行性。语言精确无歧义，读者读完知道什么必须做、什么不能做、违反了会怎样。

**必答问题**：

1. 为什么制定？依据什么上位规定？（目的与依据）
2. 适用于谁、什么范围、什么情形？
3. 具体规则是什么？每条：适用对象、触发条件、行为要求、标准、例外
4. 谁负责执行、监督、解释？
5. 违反后果是什么？如何处理？
6. 何时生效？替代或废止什么？如何修订？

**常见主线**：总则（目的、依据、适用范围、术语定义）→ 组织与职责 → 分章规则 / 流程步骤 → 监督与检查 → 违规处理 → 附则（生效、解释权、修订）→ 附件（表单、流程图）

**专属规则**：

- **规范用词分级并在总则中声明**，全文一致：
  - 必须 / 应当（must / shall）：无例外的强制要求
  - 应（should）：默认要求，偏离需说明理由并获批准
  - 可 / 可以（may）：允许但不强制
  - 不得 / 禁止（must not）：无例外的禁止
  不要用"尽量""原则上""一般"表达约束力——它们无法执行
- **R4 的例外**：条文本身只写规则，不逐条写理由。理由集中在"总则·目的"或章首一段。章首定向仍然需要（本章规范什么、为什么单列一章）
- 每条规则用"五个具体"检查，重点是对象具体和标准具体
- 责任落到岗位/部门，不落到姓名
- 违反后果必须具体到处理方式和依据（"依据《员工手册》第七章予以书面警告"），不写"将受到相应处罚"
- 编号用条/款/项体系或多级数字，全文一种
- 若用户要求套用组织既有格式（如 GB/T 9704 公文格式），格式从用户要求，内容仍遵守本文件

## 7. 工作汇报 / 情况说明

**侧重**：针对性、时效性。直接回应对方的关切，篇幅精炼。

**必答问题**：

1. 目标达成了吗？（一句话结论放最前）
2. 做了什么、结果如何？（只写与目标相关的）
3. 与上次相比什么变了？为什么？（变化项优先于存量项）
4. 有什么问题或风险？影响多大？
5. 需要对方做什么决策、提供什么支持？（明确到选项）

**常见主线**：结论（完成情况一句话）→ 关键进展与结果 → 变化、问题与风险 → 需要的决策/支持 → 下一步计划 → 附件（详细数据）

**专属规则**：

- 直接模式（H7）几乎总是适用：首段就是答案，不要从背景讲起
- 需要决策时给选项 + 建议 + 各选项代价，不只提问题
- 篇幅通常短，但"结论 + 依据"最低要求不变；短不是简单罗列的理由
- 情况说明（对某一事件的解释）：时间线要完整、事实与判断分开、责任归因到机制

---

## 8. 总结 / 复盘

**侧重**：真实性、分析深度、可复用。读者要能带走可迁移的经验，不是看一遍流水账。

**必答问题**：

1. 原目标是什么？（用当时的表述）
2. 实际结果是什么？与目标的差距？
3. 差距的根因是什么？（追到机制/流程/条件层面，不停在"重视不够"）
4. 哪些做法有效，值得沉淀为标准做法？为什么有效？
5. 后续改什么？谁负责？何时验证？

**常见主线**：目标回顾 → 结果与差距 → 做得好的与原因 → 差距与根因分析 → 沉淀的经验与改进项（含负责人）→ 附录

**专属规则**：

- 根因分析至少追两层"为什么"，直到落在可改变的机制/流程上
- 归因到机制不归因到态度（style-guide.md 第 6 节）
- "经验"必须写成可迁移的判断（"在 X 条件下应 Y，因为 Z"），而不是事件描述
- 改进项遵守 R9：谁、做什么、何时验证

---

## 9. 混合与边界情况

- **用户要求的文体不在列表**（如会议纪要、请示、建议书、白皮书）：找最接近的文体（请示≈汇报 + 方案；建议书≈方案 + 说服；白皮书≈研究报告 + 方案），叠加 §0 三问推断必答问题。
- **一份文档跨多个文体**（如"复盘 + 下一步方案"）：主线上先复盘后方案；两部分各自满足其必答问题；用一个承接章说明复盘发现如何导出方案。
- **用户给了模板但模板与文体必答问题有缺口**：模板优先（用户明确要求），缺口内容放进最接近的模板章节，或在交付说明中提示建议增补的章节。
- **用户只给一句话需求，没有材料**：先判断哪些是关键模糊（R8）去问；方法论层面用领域知识写足；数字层面用"[待确认]"占位并遵守 R6。宁可交付一份结构完整、方法具体、关键数字待填的文档，也不要编数字。
