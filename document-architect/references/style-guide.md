## 1. 使用方式

本文件是 SKILL.md §3.3 和工作流第四步"修改润色"的校验参照。写完初稿后，按第 2-6 节顺序各过一遍。**每一条都是启发式**：出现在下面"少用"栏的词并非禁用，而是"出现时停一下，问自己这个词提供了什么信息"。唯一的硬规则是 SKILL.md 的 R9（责任句有主语）。

## 2. 平实语言：词汇层

**原则**：用读者理解并习惯的词。判断标准不是"简单"，而是"读者是否需要停下来解码"。给安全工程师写"横向移动"不需要解释；给财务总监写就要解释或换说法。

### 2.1 不提供信息的官话/套话（默认删除）

进一步、切实、扎实、大力、深入、全面（无具体范围时）、有关、相关（无具体指向时）、一定程度上、在……方面、从……角度来看、众所周知、不言而喻、需要指出的是、值得注意的是（后面若真有值得注意的内容，直接写内容）

### 2.2 模糊量词（改为具体值或明确说不确定）

| 少用 | 改为 |
| --- | --- |
| 尽快、及时 | 具体日期或时限："3 个工作日内" |
| 大幅、显著、明显 | 具体幅度："下降 23%"；不知道就写"幅度待测算" |
| 多数、部分、少量 | 数字或比例；确实无数据则写"抽样 20 个中 14 个" |
| 适当、合理、有效 | 写出标准："响应时间 ≤ 4 小时" |

### 2.3 术语处理

- 读者是领域内人 → 直接用，不解释。
- 读者是跨领域/管理层 → 首次出现给一句解释或括注；超过 5 个术语考虑加"术语说明"节。
- 同一概念不要在专业术语和通俗说法之间切换（见第 5 节）。

## 3. 句子层

### 3.1 一句一意

一个句子只承载一个判断或一个动作。出现"并且/同时/此外"串起两个不同判断时，拆句。出现三层以上嵌套定语（"基于……的、面向……的、具有……特征的系统"）时，拆句或改列表。

### 3.2 主语明确（R9 的实施细则）

责任句 = 说"要做什么"的句子：措施、步骤、要求、建议、承诺。检查方法：对每个责任句问"谁？"，答不出来就补。

| 不合格 | 合格 |
| --- | --- |
| 将对现有流程进行梳理 | 运营部在 4 月底前完成现有流程梳理 |
| 相关问题需要得到解决 | 项目经理负责在下次周会前关闭 3 个遗留问题 |
| 建议加强安全培训 | 建议安全部每季度组织一次面向全员的钓鱼演练，点击率目标 < 5% |

**主语可以是角色/部门，不必是姓名**，除非用户要求到人。

### 3.3 主动语态的适用边界

默认主动。以下情况被动或无主句是合法的，不要机械改写：

- 施动者不重要或不言自明："本制度自发布之日起施行"
- 施动者是泛指或不宜点名："该漏洞已在公开渠道被披露"
- 强调受动对象："核心数据库须每日备份"（制度条文常见）

判断标准只有一个：**读者是否会因为不知道"谁"而产生歧义或无法行动**。会，就改主动；不会，可以保留。

### 3.4 名词化改动词

| 名词化 | 直接动词 |
| --- | --- |
| 对 X 进行评估 / 分析 / 梳理 | 评估 / 分析 / 梳理 X |
| 开展 X 工作 | X（如"开展培训工作" → "培训"） |
| 实现 X 的提升 | 提升 X |
| 加强对 X 的管理 | 说清管理动作："每周审核 X 的访问日志" |
| 做好 X 的保障 | 说清保障动作 |

"加强/做好/推进"后面若写不出具体动作，说明还没想清楚，回到内容之柱补内容，而不是换个词。

## 4. 段落层：删赘与去软化

### 4.1 删赘三问

逐段逐句问：

1. 删掉这段，读者会少知道什么？—— 什么都不少 → 删（R4）。
2. 删掉这句，段落论点会变弱吗？—— 不变 → 删。
3. 删掉这个词，句子意思变吗？—— 不变 → 删。

**不属于赘物**：判断、依据、条件、数字、时间、角色、标准、风险的触发条件、示例（如果它帮助理解）。压缩篇幅时不动这些（SKILL.md A7）。

### 4.2 软化词处理

| 软化写法 | 问题 | 改法 |
| --- | --- | --- |
| 可能会在一定程度上影响进度 | 三重缓冲，读者不知道到底影响不影响 | 若确定：影响进度约 2 周。若不确定：进度影响取决于 X 是否在 3 月前到位，到位则无影响，否则延后约 2 周 |
| 基本上完成了 | 完成了多少？ | 已完成 8 项中的 7 项，剩余 1 项预计 X 日完成 |
| 相对而言效果较好 | 相对什么？ | 与方案 B 相比，方案 A 的部署时间短 40% |

原则：**不确定性要显式化——说清不确定的来源（缺什么信息）和范围（影响多大）**，而不是用软词把它糊住。

### 4.3 兜底句（R6 细则）

同一含义的免责兜底全篇一处，放在"假设与前提""边界""说明"类章节。正文各处需要提示时，用具体条件替代兜底："若甲方在 T+5 前未提供测试账号，本阶段起止时间相应顺延"，而不是"具体以双方确认为准"。

## 5. 一致性：术语、称谓、格式

**做法**：第二步规划时列术语表，形如：

| 概念 | 全文统一称法 | 不用 |
| --- | --- | --- |
| 系统使用者 | 用户 | 客户、使用人、终端用户 |
| 委托方 | 甲方 | 客户、贵司、XX 公司（除首次全称） |

**检查项**：

- 同一实体一个名字（含缩写：首次"全称（简称）"，之后只用简称）
- 称谓体系不混用：选定"甲方/乙方"就不再夹杂"贵司/我司"
- 数字：万/亿 vs 千分位、百分数保留位数、货币单位，全文一种
- 日期：2026-03-15 / 2026 年 3 月 15 日 / 3 月 15 日，全文一种
- 同级标题句式平行（都是名词短语，或都是结论句，不混）
- 摘要中的结论、正文中的结论、结论章的结论，三处口径一致——这是最常见的不一致来源，定稿前专门对一遍

## 6. 礼貌：语气校准对照表

礼貌 = 尊重、专业、得体，**不是客套话堆砌**。"敬请""恳请""烦请"每篇 1-2 处足够。

| 读者关系 | 得体 | 不得体 |
| --- | --- | --- |
| 向上汇报 | "建议采用方案 A，理由是……；如更看重成本可选方案 B，代价是……" | "必须立即批准方案 A" / 只给一个选项不给理由 |
| 向下布置 | "各组在 X 日前完成 Y，标准是 Z；这样安排是因为……" | "各组务必高度重视，切实抓好落实" |
| 对外（客户/合作方） | "为保障 X 目标，需要贵方在 T 前提供 Y" | "贵方未按时提供 Y 导致延误" |
| 复盘中指出问题 | "该环节的检查点缺失，导致问题在 3 天后才暴露" | "XX 没有认真检查" |
| 否定对方方案 | 先陈述共同目标和对方方案的合理之处，再给出不采纳的具体依据（H7 间接模式） | "该方案不可行" |

**复盘/评估类的特殊要求**：问题归因到**机制、流程、条件**，而不是归因到人的态度。这既是礼貌，也是分析深度的要求——归因到态度就没有可复用的经验。

## 7. 中文正式文体的特殊说明

- "的"字连用超过两个通常意味着定语过长，拆句。
- 四字套语（"高度重视、精心组织、周密部署"）在制度/公文中若用户要求或所在组织习惯可保留，但**不能替代具体内容**：套语之后必须跟具体的谁、做什么、什么标准。
- 中文可以无主句，但责任句不行（R9）。
- 平实语言不等于口语化。"咱们""搞定""挺好的"不出现在正式文档中，正式度由文体决定（SKILL.md A5）。
