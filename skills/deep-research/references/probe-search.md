## 核心目标

用最少的高价值探针,补齐会影响用户**结论、行动、方向、风险、资源投入或机会判断**的证据缺口。

Probe-Search 不是为了穷尽所有资料,而是为了在有限成本下达到"足以帮助用户决策"的证据质量。

## 适用场景

当任务满足以下任一条件时启用:

- 用户需要决策、比较、选型、评估、投资、战略判断。
- 任务涉及市场、竞品、法规、价格、技术趋势、供应商、风险、机会。
- 答案可能因时间、地区、行业、来源不同而变化。
- 需要综合多个来源,或需要发现反方、边界条件、隐藏约束。
- 用户明确要求调研、搜索、验证、找最新信息。

## 不适用场景

以下场景默认不启用,除非用户明确要求:

- 改写、翻译、润色、总结用户已提供文本。
- 低风险常识问题。
- 创意写作。
- 用户明确要求不要联网或不要扩展调研。
- 已有材料足够完成任务,不需要外部事实。

## 总原则

1. **先决策,后搜索**:先明确用户要做什么判断,再决定搜什么。
2. **先关键缺口,后背景信息**:优先补齐会改变结论的证据。
3. **先一手来源,后二手解读**:关键数字和事实尽量锚定原始来源。
4. **先反证,后加证**:不要只找支持性证据。
5. **先边界,后细节**:先确认适用范围、约束、风险,再补细节。
6. **看信息增益,不看搜索数量**:继续搜索的理由必须是它可能改变判断。
7. **允许 agent 主动转向**:默认规则是护栏,不是脚本;agent 可在说明理由后 pivot、升级、降级或停止。

## 计量单位与任务卡

- **round / probe 的定义见 SKILL.md §4.2**(全文唯一权威:round = 1 次成功搜索调用,probe = 1 次有目的的信息动作)。
- **任务卡模板见 SKILL.md §4.1**(唯一权威)。下面只补充几个字段的填写指引——它们不在 SKILL.md 模板里展开,但直接影响搜索策略:

### 增量字段填写指引

- **决策后果**(低/中/高):错误答案的代价是什么?是否涉及金钱、法律、医疗、安全、战略或不可逆选择?后果越高,越倾向一手来源与完整红队。
- **范围边界**:时间 / 地理 / 行业 / 价格预算 / 排除项,任一不清都会让搜索无效——优先在 Frame 阶段锁定。
- **来源要求**:关键数字是否必须一手来源?是否需要官方 / 学术 / 监管 / 财报 / 行业报告?有无禁用或低权重来源?
- **输出要求**:用户要结论先行 / 表格比较 / 风险清单 / 推荐方案 / 下一步行动?影响报告形态,也影响搜索侧重。
- **当前不确定性**:已知未知、可能隐藏约束——这些就是第一批 probe 的靶子。

## 来源等级

| 等级 | 来源类型 | 使用规则 |
| --- | --- | --- |
| A | 官方文件、监管数据、公司财报、标准文件、论文原文、权威数据库 | 可支撑关键事实、数字、法律/政策/技术标准 |
| B | 系统综述、权威机构报告、专业媒体、知名咨询/分析机构 | 可支撑综合判断和趋势判断 |
| C | 行业文章、专家评论、博客、播客、新闻解读 | 可作解释、观点、线索 |
| D | 论坛、社媒、厂商营销页、匿名内容、聚合站 | 只作线索,不单独支撑结论 |

### 来源规则

- 关键数字尽量追溯到 A 级来源。
- 关键判断至少需要 1 个 A/B 来源,重要判断尽量需要多个独立来源。
- 多个媒体引用同一个原始数据,只算一个独立证据源。
- 厂商材料可用于了解产品主张,但不能单独支撑"最好、最安全、最划算"等判断。
- 如果来源之间冲突,必须说明冲突来自时间、口径、样本、地区、定义还是利益立场。

## 工作量等级

按 **probe 数**规划研究节奏,按 **round 数**(SKILL.md §4.2)检查硬上限。

| 等级 | 适用场景 | 默认 probe 数 | 典型来源检查量 |
| --- | --- | ---: | ---: |
| L1 快速 | 边界清楚、低风险、1-3 个高质量来源即可回答 | 2-5 | 3-8 |
| L2 标准 | 需要比较、互证、反方检查、多个维度评估 | 5-12 | 8-25 |
| L3 复杂 | 高风险、跨域、多冲突、战略/投资/法律/医疗/重大采购 | 10-25 | 20-60 |

工作量在 probe 2-5 次后定档,可中途升降级。

### 升级规则

从 L1 升级到 L2:

- 出现高可信冲突。
- 发现关键数字没有一手来源。
- 用户决策后果高于预期。
- 初始假设被削弱但未被推翻。
- 发现新的关键维度。

从 L2 升级到 L3:

- 多个权威来源互相冲突。
- 结论对金钱、法律、医疗、安全、战略有重大影响。
- 需要跨行业、跨地区或跨时间比较。
- 需要估值、预测、政策解读或复杂 trade-off。

### 降级规则

可以提前停止或降级:

- 用户目标已被满足。
- 进一步搜索只会增加背景知识,不会改变建议。
- 连续两个 probe 无决策相关增益。
- 需要用户补充范围、偏好或约束,否则继续搜索无效。

## Probe 类型

| Probe 类型 | 目的 | 典型问题 |
| --- | --- | --- |
| P1 范围探针 | 明确问题边界和主要维度 | 这个领域的主流分类、核心指标是什么? |
| P2 一手来源探针 | 锚定关键事实和数字 | 官方数据、财报、监管文件怎么说? |
| P3 对比探针 | 找差异、优劣、benchmark | A 与 B 在价格、性能、风险上差在哪? |
| P4 反方探针 | 主动寻找反证和批评 | 谁不同意?反对理由是什么? |
| P5 冲突解释探针 | 解决来源矛盾 | 冲突来自时间、口径、样本还是定义? |
| P6 风险探针 | 发现隐藏约束 | 法规、实施、成本、兼容性、供应链风险是什么? |
| P7 时效探针 | 确认最新状态 | 最近是否有政策、价格、版本、事件变化? |
| P8 用户/市场探针 | 发现真实使用反馈 | 用户抱怨、采购障碍、市场接受度如何? |
| P9 决策探针 | 判断是否足够行动 | 现在是否足以推荐、排除、等待或继续验证? |

## 每轮执行循环

每个 probe 后,agent 必须更新判断。

```markdown
### Probe Log

- probe_id:
- 本轮目标:
- 查询 / 来源方向:
- 找到的关键证据:
- 来源等级:
- 支持了什么:
- 削弱了什么:
- 新增风险 / 约束:
- 是否改变结论:
- 下一步:
  - stop / continue / pivot / upgrade / ask_user
```

## 信息增益评估

每轮搜索后用 **SKILL.md §4.2 的 5 key 表**(新检测 / 新深度 / 新比较 / 新视角 / 新维度)判断信息增益——本文件不再重复第三套措辞,以 SKILL.md 为唯一权威。5 key 的 Sum 即信息增益的量化。

### 信息增益等级

- **High**:改变结论、推荐、风险判断或关键边界。
- **Medium**:补齐关键证据、锚定数字、解决冲突。
- **Low**:增加背景信息或重复支持。
- **Zero**:没有新增有效信息。

### 处理规则

- 连续 1 个 Zero:必须 pivot,换查询词、来源类型、地区、时间范围或反方角度。
- 连续 2 个 Zero:若无高风险未决项,停止并进入 Decide。
- 连续 2 个 Zero 但仍有高风险未决项:升级任务等级或向用户请求澄清。
- 只有 Low 增益不能作为继续深挖的充分理由,除非任务是高风险或用户要求全面综述。

## 停止条件细化判据

停止条件 S1-S7 的权威定义见 SKILL.md §4.2(满足任一即进 Decide)。下面只补充每条的**细化判据**,帮助判断何时算"满足":

| # | 条件 | 细化判据 |
| --- | --- | --- |
| S1 | Must-have 全部满足 | Must-have 全勾选;Nice-to-have 达到目标比例;结论足以指导行动 |
| S2 | 主要分歧已解决/未决 | 冲突已处理,或明确标为 unresolved 且不影响当前行动 |
| S3 | 颠覆性反证 → 假设无效 | 高可信反方已验证,足以 kill 或 reframe 原假设(任务需 reframe) |
| S4 | 达到 round 硬上限 | 机械判定:`check-stop --effort L?`(L1=20 / L2=50 / L3=80) |
| S5 | 连续 2 probe 零增益且无高风险未决项 | 见上方"处理规则";只有 Low 增益不构成继续深挖的理由,除非高风险或用户要求综述 |
| S6 | 缺用户偏好/预算/约束 | 缺少偏好 / 预算 / 地区 / 风险承受度,继续搜索无法有效推进 → 问用户 |
| S7 | 依赖最新状态无法验证 | 任务依赖最新状态,但无法确认最新信息 → 带不确定性输出 |

## Agent 自主权与 override 记录

自主权的权威授权见 **SKILL.md §3**(你的自主区)。本文件只补充 override 的记录格式——默认规则是护栏不是脚本,agent 可以在说明理由后偏离,但偏离必须留痕。

### override 记录格式

agent 可以在说明理由后:

- 跳过某个默认 probe;
- 提前停止;
- 从 L1 升级到 L2/L3;
- 从 L2/L3 降级;
- 改变任务卡中的范围;
- 请求用户澄清;
- 将原问题 reframe 成更有决策价值的问题。

但必须记录:

- **为什么** override;
- override **影响哪个结论**;
- **是否增加风险或不确定性**。
