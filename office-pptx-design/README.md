# office-pptx-design —— 工作类幻灯片创作

> 为汇报、总结、述职、培训、方案演示等正式工作场景**想清楚、查清楚、写清楚**一整套 PPT：受众与目标澄清 → 多渠道调研与事实交叉核查 → 结论式大纲 → 逐页内容与视觉意图 → 讲稿，再交由 ppt-master 生成原生 PPTX 并做交付前自检。

## 这是什么 / 给谁用

**不是**：把一份 Word 报告排版成幻灯片，或只调整现有 PPT 的版式。**而是**：一套工作类 PPT 的内容创作规范——一份 PPT 的唯一目的是**让特定受众在有限时间内抓住一条核心信息并做出预期反应**。它负责"想清楚、查清楚、写清楚"；"画出来、导出来"由 [ppt-master](#与-ppt-master-的分工) 完成。

| 角色 | 典型场景 |
| --- | --- |
| 职场汇报人 | 年终总结、述职、阶段汇报、复盘材料 |
| 培训 / 安全岗 | 面向全员的培训课件、宣讲材料 |
| 方案负责人 | 提案、方案演示、项目立项材料 |

**不适合**：单页海报、Word 报告、纯数据看板、仅修改现有 PPT 排版（后者直接走 ppt-master 的 Edit Native PPTX）。

**触发时机**（见 [`./SKILL.md`](./SKILL.md) frontmatter 的 `description`）：用户提到"做一份 PPT / 幻灯片 / deck / 汇报材料 / 培训课件 / 述职材料 / 方案演示 / 年终总结"，或给出大纲、素材文件夹、页数、时长要求产出演示文稿——即使只说"帮我把这些材料整理成 PPT"也应触发。

## 核心能力

- **一轮问齐** — P0 用一张表澄清受众 / 目的 / 场景 / 时长页数 / 素材 / 语气禁区 / 交付形式 7 项，推断项给默认值，不分多轮零碎追问
- **事实可追溯** — 法规 / 案例 / 数据交叉核查 ≥2 个独立来源，优先官方，记录来源与查证日期；查不到写"待确认"，不编造、不用记忆填空
- **结论式大纲** — 每页标题是一句完整判断（有主语有结论），相邻页承接可用一句话说出；**大纲经用户确认后才进入逐页内容**（⛔ 门控）
- **逐页密度自检** — 每页 1 个核心观点、正文 30 秒可读完；只留 1-2 个元素或塞满 6+ 元素都判为不合格
- **交付前独立复核** — 逐页预览检查溢出 / 重叠 / 对比度 / 错别字，再用独立视角（新对话或子 agent）做 Reviewer 复核

## 快速开始

### 安装

本 skill 遵循通用的 **Agent Skills 规范**（一个目录 + 一份带 frontmatter 的 `SKILL.md`），不绑定任何特定 agent。把目录放进你所用工具的 skills 目录即可：

```bash
git clone https://github.com/0xn0ne/skills.git
cp -r skills/office-pptx-design/ <你的 agent 的 skills 目录>/
```

常见 agent 的 skills 目录：

| Agent | 用户级（全局可用） | 项目级（团队共享同一版本，推荐） |
| --- | --- | --- |
| Claude Code | `~/.claude/skills/` | `<project>/.claude/skills/` |
| OpenCode | `~/.config/opencode/skills/` | `<project>/.opencode/skills/` |
| 其他支持 Agent Skills 的工具 | 按其文档指定的 skills 目录 | 同上（团队共享同一版本） |

> 不安装也能用：直接在 prompt 里给出 `SKILL.md` 的绝对路径，让 agent 加载即可。

自检（以 Claude Code 用户级为例）：`ls ~/.claude/skills/office-pptx-design/SKILL.md` 应能列出文件。

**依赖说明**：生成阶段（P4）需要 ppt-master 技能（`skills/ppt-master/`，不在本仓库内，需另行准备）。只有本 skill 时，仍可独立完成 P0-P3 的澄清、调研、大纲与逐页内容产物，把它们交给任何能生成 PPT 的工具或人工。

### 最小调用（给 agent 的 prompt 模板）

```text
你要为一次正式工作场景制作 PPT。

任务：[场景与主题，如：面向全员的年中安全意识培训 / 给管理层的年度复盘汇报]
素材：[素材文件夹 / 文件路径，或直接粘贴]
约束：[页数 / 时长 / 模板 / 品牌规范，可选]

加载 SKILL（绝对路径）：<你的 skills 目录>/office-pptx-design/SKILL.md
按 P0-P5 流程执行：P0 一轮问齐；大纲经我确认后再逐页展开；生成阶段配合 ppt-master。
```

> prompt 里只给任务、素材与路径，不要复述 SKILL 的规则。

### 预期输出

| 产出 | 形式 | 成功判据 |
| --- | --- | --- |
| `project_notes.md` | 需求 7 项（已知 / 推断 / 未知）+ 已决策 + 待确认 + 阶段状态 | 7 项全部有明确答案或用户确认的默认值 |
| `sources.md` | 每条事实：编号、陈述、≥2 来源、日期、可信度、用于第几页 | 法规 / 案例 / 数据均可追溯 |
| `outline.md` | 每页：结论式标题 + 目的 + 要点 + 视觉 + 承接 + 时长 | 用户已确认 |
| `content.md` | 每页内容要点 + 视觉意图 + 讲稿（含时长与过渡句） | 每页 1 个核心观点，正文 30 秒可读完 |
| 交付包 | `.pptx` + 讲稿 + `sources.md` + 自检清单勾选结果 + 待确认清单 | [§9 自检清单](./SKILL.md)逐项通过 |

## 工作流（P0-P5）

```text
P0 澄清(一轮问齐) → P1 调研与核查 → P2 大纲 ⛔用户确认 → P3 逐页内容与视觉意图 → P4 生成与复核(ppt-master) → P5 交付
   7 项需求列表        反推查证清单       结论式标题            要点≤20字/条          逐页预览检查          .pptx + 讲稿
   已知/推断/未知      ≥2 独立来源        承接 + 时长分配       视觉意图 + 讲稿       独立 Reviewer 复核    来源清单 + 自检
```

- **P0 澄清**：读完用户全部材料后，一张表列出 7 项并标注"已知 / 推断（待确认）/ 未知"，推断项给默认值，用户不反对即采用；写入 `project_notes.md`，之后每阶段更新一次。
- **P1 调研**：从大纲需求反推查证清单，多渠道并行（官方 > 行业组织 > 头部企业/咨询机构 > 技术社区，社区只作线索）；每条事实交叉核查 ≥2 来源，法规再核"现行有效"与条款原文；有争议或查不实的单列"待确认"交用户。
- **P2 大纲（⛔ 用户确认）**：按模板产出 `outline.md`——标题是完整判断句、相邻页承接说得出一句话、时长分配之和等于总时长（每页 45-90 秒常态）；全员场景随机抽 3 页自问"非技术岗员工看这页有关系吗？"。**未经确认不得进入 P3。**
- **P3 逐页内容**：为每页写 `content.md` 条目（标题 / 要点 3-5 条每条 ≤20 字 / 视觉意图 / 讲稿 / 来源编号）；密度自检：一页超 6 个元素或正文超 90 字 → 拆页或砍。
- **P4 生成与复核**：读 `skills/ppt-master/SKILL.md` 并完全遵循其路由与门控，把 `outline.md`、`content.md`、`sources.md` 与素材交给它；生成后逐页看预览，再用独立视角（只给它 `outline.md` 和预览）做 Reviewer 复核；修订循环上限 3 轮，仍不达标带问题清单上报。
- **P5 交付**：交付 `.pptx`、讲稿、`sources.md`、自检清单勾选结果与"待确认 / 已知限制"清单。

各阶段完成标准与证据要求见 [`./SKILL.md`](./SKILL.md) §1.2（DONE_WHEN）：不接受自证"已完成"，每阶段须提交证据。

## 红线速览

细节见 [`./SKILL.md`](./SKILL.md) §2，此处只做索引：

| # | 红线 | 一句话 |
| --- | --- | --- |
| 1 | 事实可追溯 | 法规 / 案例 / 数据交叉核查 ≥2 来源，标注来源与查证日期；查不到写"待确认"，不编造 |
| 2 | 敏感信息脱敏 | 客户 / 内部数据默认脱敏或概括化，需出现原始信息先问用户 |
| 3 | 语气中性 | 正式客观，用"现状 / 风险 / 建议"，不指责部门或个人，全员材料不偏向岗位 |
| 4 | 一页一观点 | 标题即结论；禁止一页多个并列论点、多张图表堆叠 |
| 5 | 图表诚实 | 坐标轴从零起（或标注截断）、单位统一标注、类型匹配数据关系、每张图标来源 |
| 6 | 门控 | 大纲经用户确认才进逐页内容；导出前关键决策（模板 / 风格 / 页数）再确认一次 |
| 7 | 不越界扩展 | 不添加用户未要求的章节或页数；发现该补的内容，先提出建议再做 |

## 场景速查

| 场景 | 受众典型关切 | 推荐结构 |
| --- | --- | --- |
| 工作汇报 / 总结 | 结果、差距、下一步、要什么支持 | 金字塔：结论 → 关键成果 → 问题与原因 → 计划 → 需求 |
| 述职 | 职责履行、价值、成长、目标 | 职责 → 成果（对应职责）→ 不足与改进 → 下阶段目标 |
| 培训 / 宣讲 | 与我有什么关系、我该做什么 | 认知 → 风险与案例 → 自身相关现状 → 应知应会 → 小结 |
| 方案 / 提案 | 解决什么问题、要多少、风险、为什么是你 | SCQA 或 现状 → 目标 → 方案 → 价值 → 计划与投入 → 风险 |
| 复盘 | 发生了什么、为什么、以后怎么防 | 时间线 → 影响 → 根因 → 已做/待做措施 → 机制改进 |

每页节奏 45-120 秒（案例 / 图解页可长）；结构可混用，依据是受众的决策路径。完整表格（含特别注意项）见 [`./SKILL.md`](./SKILL.md) §5。

## 与 ppt-master 的分工

本 Skill 与 ppt-master 按"想 / 画"分工，进入生成阶段时**先读 `skills/ppt-master/SKILL.md` 并完全遵循其路由与门控**，本 Skill 不覆盖、不简化它的流程：

| 阶段 | 归属 | 产物 |
| --- | --- | --- |
| 需求澄清、调研核查、大纲、逐页内容、视觉意图、讲稿 | 本 Skill | `project_notes.md`、`outline.md`、`sources.md`、`content.md` |
| 模板/风格选择、SVG 逐页绘制、图表与图片生成、导出 PPTX | ppt-master | `.pptx` 及其工作区 |
| 交付前复核、修订循环 | 本 Skill 发起，ppt-master 执行修改 | 自检报告 |

内容问题改 `content.md` 再生成；视觉问题走 ppt-master 的修订路径。ppt-master 自身的 ⛔ 门控同样遵守。
