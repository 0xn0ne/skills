## 公共基础:5 章节结构

```
# 报告名称
## 执行摘要
...300-500 字
## 关键发现
...说明意义，证据 + So-what
## 洞察与跨领域
...领域内洞察 + 跨领域洞察
## 风险与红队分析
...4个视角 + Steel-man + 剩余风险
## Conclusions
...可执行下一步建议或措施,Who/What/When
```

无论 lens 如何叠加,5 章节保留。lens 只调整章节权重,不增减章节。

### 4 视角(red team 领域型范畴)

章节 4 的"4 视角"指:**技术 / 商业 / 监管 / 行为** 四个领域范畴,domain-based 而非 functional。Steel-man 协议与假设追踪规范见 `references/hypothesis-redteam.md`,本 reference 不重复。

## 6 lens 章节权重表

| lens | ES | Findings | Insights+CD | Risks+RT | Conclusions | 假设追踪 |
| --- | --- | --- | --- | --- | --- | --- |
| 决策 (decision) | 重 | 中 | 中 | 重 | 重 | ✓ 必需 |
| 比较 (comparison) | 中 | 重 | 重 | 中 | 重 | ✓ |
| 证据综述 (synthesis) | 重 | 中 | 重 | 轻 | 中 | ✓ |
| 现状扫描 (scan) | 轻 | 重 | 轻 | 跳 | 中 | × |
| 基准评测 (benchmark) | 中 | 重 | 中 | 中 | 重 | × |
| 探索研究 (exploratory) | 轻 | 中 | 中 | 跳 | 重 | ✓ |

权重含义:重 = 章节重头 / 中 = 标准展开 / 轻 = 简短 / 跳 = 不出现。

- **假设追踪**列与 SKILL.md §5 启用条件一致(竞争假设 + 4 态追踪 ∈ {决策, 比较, 证据综述, 探索})。
- **Cross-Domain 是 Insights 的固定子模块**,深度随 "Insights+CD" 列权重同步缩放,无独立启停门。

## 主+副叠加语法

```yaml
任务卡:
  primary_lens: <必填,1 个>
  secondary_lens: <可选,0-2 个>
```

副类型上限:

- 0 副 = 默认(纯 primary)
- 1 副 = 推荐(常见 hybrid: 决策+比较)
- 2 副 = 允许(复杂 hybrid: 决策+比较+探索)
- 3+ 副 = 拒绝,合并到 primary 字段

叠加规则:

- ES 重 × ES 重 → ES 重(不叠加,取最重)
- 任一启用 Cross-Domain → 总启用(轻量)
- 假设追踪:primary 启用即启用

## 5 个 boundary 判别规则

| 边界 | 判定问题 | YES → 类型 |
| --- | --- | --- |
| 比较 vs 决策 | "是否需要单一推荐?" | YES → 决策 |
| 比较 vs 基准评测 | "是否含硬量化 perf 数字?" | YES → 基准评测 |
| 决策 vs 探索 | "是否能拿可逆实验验证?" | YES → 决策 |
| 证据综述 vs 现状扫描 | "主要存在知识分歧?" | YES → 证据综述 |
| 现状扫描 vs 探索 | "已有书面知识可盘点?" | YES → 现状扫描 |

答不上来或冲突 → primary default = 决策(lens 体系最通用)。

## 写作技法

每章节标题必须承载一句结论(`## Key Findings: 5-8% 加速 + 1.61× asyncio`),不写 `## Key Findings` 这种 topical label。

句段级技法见下方「通用写作技法」。交付前的 8 项 Decision-Readiness 自检在 **SKILL.md §7**(本文件不再重复)。

## 受众适配输出 — 9 条通用原则 + 3 路径 + 4 失败模式

报告"对的人看得下去、看完能决策"。下面是**启发式**而非规则,agent 按内容自主选用,不为某类人写"平行段"。

### 9 条通用原则(每条 ≤ 2 行)

| # | 原则 | 一句话 |
| --- | --- | --- |
| P1 | 倒置结论 (BLUF) | 第一段就是答案,读完即可行动 |
| P2 | 分层深度 | 同一内容在 30s/5min/30min 三档深度下各自独立成立 |
| P3 | 重构非翻译 | 检测到受众差时改**论证骨架**,不替换同义词 |
| P4 | 认知负荷 ≤ 4 chunk | 每节最多 3-4 个信息块,超出拆节或挪附录 |
| P5 | 路径分叉 | 设计多条入口(标题/ES/章首句),不替读者选唯一路径 |
| P6 | 具体度校准 | 同一事实的粒度随读者调整(决策者要业务后果,技术人要数字) |
| P7 | "So what?" 测试 | 每段自问"对这位读者意味着什么、该做什么" |
| P8 | 锚+类比+含义 | 跨专业读者时强制:锚已知 → 类比 → 含义,光简化措辞不够 |
| P9 | 多入口锚点 | 30s / 5min / 30min 各自独立可读,缺一条路径则该路径读者失败 |

### 3 条阅读路径(数学实证)

| 路径 | 时长 | 字数 | 入口 |
| --- | --- | --- | --- |
| 30 秒 skim | ≤ 30s | 75-100 词 | 标题 + 第一段 |
| 5 分钟 mid | 1-5 min | 250-750 词 | ES + 章首句 + 每章 declarative heading |
| 30 分钟 deep | 30 min+ | 1500-3500+ 词 | 全文 + 附录 |

任一路径缺失 → 该路径的读者失败。三层独立可读 ≠ 三份内容,是同一内容在三档深度下都能站立。

### 5 类受众推断信号(命中 ≥2 直接渲染,<2 + 影响结构则问 1 题)

| 信号 | 命中例子 |
| --- | --- |
| 词汇 | funding/IRR/API/p99/GDPR/strategy |
| 人称 | "我们应该…" / "X 行业怎样" |
| 时间紧迫 | "urgent" / "TL;DR" / "comprehensive" |
| 深度-广度 | "列出所有…" / "为什么…" |
| 词汇熵 | 高熵+专业=专家;低熵+口语=新手 |

**默认受众 = 决策者**(最容易被淹没)。命中 <2 且结构会被改变 → 任务卡问 1 题(≤3 题)。

### 4 个失败模式(自检)

| 失败 | 修复 |
| --- | --- |
| **叙事渗漏** | lens / probe count / skill version 进正文 → 移附录"方法说明" |
| **证据可见度** | `[S1][S2]` 短引用 + 末尾 sources → 写完报告后用 `scripts/research_tools.py inline` 自动注入 inline 元数据(title / tier / date),再快速审核 |
| **时间模糊** | "最近/目前/即将" → 用 anchor date(YYYY-MM 或 YYYY-Qx) |
| **认知地位标签** | "已确认 / 已公开 / 自推断 / 未验证" 四档至少用 2 档 — 工具自动提示: `python3 scripts/research_tools.py suggest-label --sources S1,S2` |

### 4 档认知地位标签

| 标签 | 含义 | 触发条件 | 自动启发 (工具一致) |
| --- | --- | --- | --- |
| **已确认** | ≥2 一手来源 + 全部一手,**已被多源核实** | ≥2 个独立一手公告 / 监管文件 / 互证新闻 | `sources ≥ 2 AND all一手` |
| **已公开** | ≥1 一手单源已发布,未交叉验证 | 财报 / 新闻稿 / 政府公告 / 公司声明 | `一手 ∈ tiers AND not all一手` |
| **自推断** | 基于公开事实的合理推论,含明确假设 | 模型预测 / 分析师估算 / 类比推理 | `二手 ∈ tiers OR sources < 2` |
| **未验证** | 仅 UGC / 社交媒体 / 匿名,未核实 | 传闻 / 未核实 UGC | `tiers = only 传闻 / empty` |

每条事实陈述至少带**1 档**标签 + 时间锚。未来预测额外标注"假设/估算/误差范围"。

**脚本辅助**(减少 agent 心智负担):

- 边记录:`python3 scripts/research_tools.py claim "<text>" <label> [--sources S1,S2]`
- 标签拿不准:`python3 scripts/research_tools.py suggest-label --sources S1,S2`(基于上表启发式)
- 写报告前:`python3 scripts/research_tools.py claims-dump` — 按 4 档分组输出,可直接拼到报告

### Inline 元数据脚本

报告写完后,执行 `scripts/research_tools.py inline --write <file.md>`,自动将 `[S1]` → `[S1: 标题 (来源, 日期), tier]`。详见 `scripts/research_tools.py --help`。

**遵守原则不替换 agent 主观能动性**:agent 仍可决定章节权重、cross-domain 启不启用、结论如何措辞;原则只在交付前提供自检参考。

### 用户额外指定的内容

**默认版式永远不变**:5 章公共基础(ES / Findings / Insights+Cross / Risks+Red / Conclusions)。agent 不主动加章节。

**当用户提示词里除了"研究/对比 X"还明确要求了具体内容**(落地细节 / 方案 / 代码 / 成本 / 时间线 / 风险预案 / 推荐矩阵 / 步骤 / 测试用例 …),agent 可在第一章节之后的任意合适位置加入新章节或并入现章节,以服务内容最优呈现为原则。

**新章节位置自主权**:agent 自由判断 ——

- 是直接升华进现章节(如"落地细节"自然并入 Conclusions 的 #7 可执行),还是
- 新增独立章节(如"附代码示例"以附录形式放在末尾更清晰),还是
- 插入到中间(用户问"对比 + 时间线"时时间线放在 Findings 后承接)

**质量优先于结构合规**:比起套固定版式,先想"这次报告里这部分内容**最该出现在哪里、最能用读者最容易接收的形态呈现**"。

**没说就默认**:纯"研究 X" / "对比 X Y" / "评估 X" → 严格 5 章,不添任何。

### 通用写作技法 — 不管章节结构如何,这些始终适用

这些是句段级技法,服务于一个目标:读者 30 秒抓到结论,并能判断每条信息可信度。技法与内容真实性冲突时,内容优先。某技法在当前文体不适用时,跳过,不硬凑。不追求覆盖率,追求读者收益。

#### A 级 · 硬约束(违反即返工,任何文体适用)

| 规则 | 判据 | 反例 ❌ | 正例 ✅ |
| --- | --- | --- | --- |
| **答案先行** | 标题即结论;首句即判断,不铺垫 | 标题:`## 关于架构选型的讨论`<br>首句:"随着业务发展,我们面临诸多技术选择……" | 标题:`## 推荐:开源 + 60-70% Rust 投入`<br>首句:"建议 2026-Q4 前完成迁移。" |
| | | 标题:`## 竞品分析`<br>首句:"本节将分析主要竞争对手。" | 标题:`## 结论:竞品在价格上领先,我们赢在集成`<br>首句:"拒绝跟随降价。" |
| **数字必须有据** | 有依据就写数字;无来源的数字禁止出现,宁写"未获得数据" | "预计能提升约 40% 性能"(无来源)<br>"估值大概 300 多亿" | "[已公开] 官方基准显示吞吐提升 38%"<br>"未获得 C 轮估值数据,不做估算" |
| | | "用户满意度显著提高" | "NPS 从 32 升到 51(2026-Q1→Q2 内部调研)" |
| **数字必须落地** | 每组关键数字后接:含义 → 下一步 → 谁负责 | "该项目预计投入 12 周。"(戛然而止) | "投入 12 周 → 若 Q4 上线须 2026-08 启动 → 建议平台组本周排期,owner 张三。" |
| | | "毛利率降到 18%。" | "毛利率降到 18% → 低于 25% 警戒线 → 建议冻结新招聘,由 CFO 在 Q3 财务评审拍板。" |
| **时间必须锚定** | 用 2026-Q3 / 2026-07,禁用"近期""即将" | "我们将在近期上线"<br>"该功能即将发布"<br>"当前版本存在问题" | "2026-08-15 前上线"<br>"预计 2026-Q3 发布"<br>"v1.8.2 存在该问题" |
| **动宾直接陈述** | 用 建议/拒绝/升级/延期;删空话 | "我们认为或许可以考虑适当升级"<br>"需要进一步加强对成本的管控" | "建议升级到企业版"<br>"压缩三项预算,合计降 30 万" |
| | | "对该方案应予以充分考虑和评估" | "拒绝该方案,ROI 为负" |

#### B 级 · 默认启用(常规报告/备忘录默认开,特殊文体可关)

| 规则 | 判据 | 反例 ❌ | 正例 ✅ |
| --- | --- | --- | --- |
| **一句一意** | 需读两遍的句子必拆;一段一件事 | "由于成本上升且竞品降价同时团队人手不足,我们建议延期上线并重新评估预算还要考虑是否裁撤该产品线。" | "成本上升,竞品降价,团队缺人。<br>建议延期上线。<br>预算与产品线存废,Q3 单独评审。" |
| **对比上表格** | ≥2 对象 × ≥2 维度就上表 | "A 方案 12 周、成本低但风险高;B 方案 20 周、成本高但稳定;C 方案介于两者之间……"(段落里塞对比) | 见下方独立表格示例 ↓ |
| **具体压倒抽象** | 能换成事实就换;删空形容词 | "覆盖范围广"<br>"性能优秀"<br>"团队经验丰富" | "覆盖 3 个域名、32 种语言"<br>"P99 延迟 42ms"<br>"核心 5 人平均 8 年后端经验" |
| **章节金字塔** | 标题概括其下全部;同层不重叠不遗漏 | 3.1 成本 / 3.2 价格 / 3.3 财务影响(三者重叠) | 3.1 一次性投入 / 3.2 持续运营成本 / 3.3 收益与回收期(互斥且穷尽) |

**"对比上表格"正例:**

| 方案 | 周期 | 相对成本 | 风险 | 适用场景 |
| --- | --- | --- | --- | --- |
| A · 自研 | 12 周 | 基准 | 高(依赖 1 名核心) | 追求速度 |
| B · 采购 | 4 周 | +45% | 低 | 追求稳定 |
| C · 混合 | 8 周 | +20% | 中 | 平衡型(推荐) |

> So what:若 2026-Q4 硬上线且预算紧,选 A;否则推荐 C,由架构组本周内定,owner 李四。

#### C 级 · 条件启用(命中触发条件才用,否则跳过)

| 规则 | 触发条件 | 判据 | 样例 |
| --- | --- | --- | --- |
| 认知标签 | 研究报告、尽调、决策备忘 | [已确认];[已公开];[自推断];[未验证],见`### 4 档认知地位标签`判据 | 见`### 4 档认知地位标签`章节样例 |
| 类比 | 读者对概念陌生,且存在结构相似的熟悉事物 | 锚+类比+差异点三件套:"DSpark ≈ 编译器 JIT,区别是跨 framework"。想不出准确类比就不用 | 见下方示例 ↓ |

**类比"三件套"示例:**

| 场景 | 正例 ✅(锚+类比+差异) | 反例 ❌ |
| --- | --- | --- |
| 解释 DSpark | "DSpark ≈ 编译器 JIT,区别是跨 framework 运行时优化" | "DSpark 是一种很先进的优化技术"(无锚点) |
| 解释向量数据库 | "≈ 带语义搜索的索引库,区别是按含义而非关键词匹配" | "它就像一个数据库但更强"(差异点缺失) |
| 想不出准确类比 | 直接定义:"Agent 编排 = 拆任务、派子任务、汇总结果的调度层" | 硬凑:"Agent 编排就像人生"(牵强,应删) |

#### 完稿自检(交付前跑一遍)

1. 只读各级标题,能否复述全文结论?
2. 每个数字有来源吗?每组数字后有"所以呢"吗?
3. 有无"近期/充分/进一步"类词残留?
4. 有无为凑技法而生的内容(硬造的数字/类比/表格)?有则删。
